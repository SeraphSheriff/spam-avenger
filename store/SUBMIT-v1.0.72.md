## The one new thing reviewers will push on — wildcard host access

v1.0.72 raises host_permissions from the old fixed list (11 entries) to 14, adding `https://crt.sh/*`, `https://*/*`, and `http://*/*`. The fixed-endpoint justifications in `store/CHROME-SUBMIT.md` no longer cover the manifest. Paste-ready replacements:

- `https://*/*` and `http://*/*` (website checks) — "Required for one feature only: when the user clicks the shield on a message, the extension fetches the home page of the sender's domain and of the message's main link, to tell whether that domain has a live website, a parked page, or no site at all, and to identify who hosts a live page. Spam and phishing domains are arbitrary by definition, so the check cannot be limited to a fixed list of sites. The fetch is a plain GET with no cookies and no user data, made only for the message the user chose to analyze. No page content is stored, displayed, or transmitted anywhere; only the live / parked / dead result is used, in the user's own browser."
- `https://crt.sh/*` — "Queries the public certificate-transparency log for hostnames that have carried certificates for the sender's domain. Used only to find the real hosting provider behind a proxy network, from public records. Queries concern the spammer's domain only — never the user's."
- Storage justification — the filed text must now cover THREE local uses, not two: (1) the temporary FTC / Safe Browsing report-form stash (erased after use, 30-minute expiry), (2) the user's saved name / email / ZIP / state for data-deletion demand letters, and (3) NEW in v1.0.72 — the repeat-sighting log: origin IP, sender domain, date, abuse desk used, and action taken, for senders the user has reported, kept to the newest 500 entries in `chrome.storage.local` only, never transmitted. Draft replacement:

> The storage permission is used for three things, all entirely within the user's own browser (chrome.storage.local) and never transmitted anywhere. (1) When the user clicks the FTC or Google Safe Browsing report buttons, the extension briefly saves that email's case details — its links, claimed sender, subject, and the sending server's IP and hostname — so the report form that opens in a new tab can be pre-filled for the user's review. That copy is erased as soon as the form is filled, and is deleted unused after 30 minutes. (2) The extension can draft a data-deletion demand letter to the company behind an email. For that letter, the user may choose to save their own name, email address, ZIP code, and state in local storage, entered once by the user, used only to fill in deletion-demand letters the user opens, reviews, and sends (or doesn't) themselves. (3) When the user reports a sender, the extension notes the sending server's IP address, the sender's domain, the date, the abuse desk the report went to, and the action taken, so a later message from the same sender can be flagged as a repeat and the new complaint can cite the earlier report. This log is capped at the newest 500 entries. The user can view, change, or clear their saved details at any time in the extension's popup, and uninstalling the extension removes everything. The extension has no server, no accounts, and no analytics; nothing stored is ever sent to the developer or any third party.

- AMO reviewer note (paste into the version's reviewer notes): "New in this version: to check whether a spam or phishing domain has a live website, the extension fetches that domain's home page, which requires host access to arbitrary sites (https://*/* and http://*/*). Fetches carry no cookies and no user data, happen only for a message the user explicitly analyzes, and no fetched content is stored or transmitted. The extension also records, in storage.local only, the IP, domain, date, and action for senders the user has reported, to flag repeat senders. Full detail is in PRIVACY.md, updated November 6, 2026."
